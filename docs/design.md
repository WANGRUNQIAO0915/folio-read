# 设计取舍

改界面前先读这里，别把已经想清楚的事改回去。

## 借鉴的开源项目

用 `gh repo view` 核过仓库和简介；只借交互思路，没有拷代码。KaTeX（MIT）是唯一打包进来的第三方代码，在 `assets/vendor/katex/`。

| 项目 | 它怎么做 | 这里怎么用 |
|---|---|---|
| [hypothesis/client](https://github.com/hypothesis/client) | 批注用“原话 + 前后文”（TextQuote）锚到网页文字，页面改了也尽量找回；找不到的批注标为孤立，不丢 | 划线和笔记存 `quote/prefix/suffix`；译文改动后找不到原话，卡片注明“译文已改”，笔记仍挂在段落上 |
| [zotero/reader](https://github.com/zotero/reader) | 阅读器里划线、评论、侧栏汇总，点批注跳回页面位置 | 左侧抽屉“笔记”页汇总全部讨论和笔记，可筛“待回答”，点击跳回并闪一下 |
| [edwardtufte/tufte-css](https://github.com/edwardtufte/tufte-css) | 宽屏时旁注放在正文右侧留白，窄屏收成可点开的标记 | AI 讨论和笔记做成边注，贴着对应段落；窄屏或打开原页时收成段尾角标，点开显示在段落下方 |
| [allenai/scholarphi](https://github.com/allenai/scholarphi) | 在论文原位悬停看引用、符号定义，不用翻到文末 | 引用号悬停看参考文献；“公式 (4) / 表 2 / 第 2.2 节”悬停预览、点击跳转 |
| [immersive-translate](https://github.com/immersive-translate/immersive-translate) | 段落级双语对照，可整体切换 | “译文 / 对照”两种模式，外加逐段“原”按钮只展开这一段英文 |
| [agentcooper/react-pdf-highlighter](https://github.com/agentcooper/react-pdf-highlighter) | 在 PDF 页面图层上框出批注区域 | 原页面板用字符坐标框出当前段落的位置（`layout.json`） |
| [PDFMathTranslate-next](https://github.com/PDFMathTranslate/PDFMathTranslate-next) | 译论文时保护公式和版式，双语对照 | 公式不走文字翻译，按原 PDF 用 TeX 重排；原页始终可看 |

不采用：把译文塞回 PDF 版式（中文排不进英文的位置，行宽和字号都不适合长读）；没有配置引擎时的“问 AI”按钮（没有模型就是假按钮，所以引擎为“不翻译”时这些按钮不出现）。

翻译引擎默认用本机 Claude Code 的无头模式：不需要 Key，而且它能自己读原页图核对公式和表格；想省钱或离线就换 OpenAI 兼容接口（Ollama 本地模型完全免费）。

## 交互

- 顶栏常驻，不随滚动收起：返回文献库、目录、对照、原页、笔记、字号、保存状态随时可点。
- 段落操作不藏在悬停里：点一下段落，段落上方出现带文字的操作条（Medium / Google Docs 的做法）；右键是完整菜单（桌面软件的习惯）；键盘 J/K 移动当前段，N/Q/E/R/Y/P 直接操作。
- 选中文字的浮动条参考 Zotero / Readwise：四种颜色划线、笔记、提问、原文、复制；选中后按 1–4 直接划线。
- 笔记有两处：边注（贴着段落，适合边读边看）和右侧笔记面板（按原文顺序的全部批注 + 整篇的论文笔记，适合回顾）。
- 字号、版心、行距用滑杆，调的时候阅读位置不跳。

## 版面

- 一栏正文，约 35 个汉字一行（`--measure: 35em`，18px 时约 630px），行距 1.9，段间距约一行。中文两端对齐，手机上改左对齐，避免长英文单词把字距撑开。
- 正文默认宋体（Noto Serif SC / 思源宋体），可切黑体。英文原文用衬线（Source Serif / Charter / Georgia），比正文小一号、灰一级，左侧一条细线，和译文明显分层。
- 数字统一等高（lining），表格用等宽数字；表格是书籍式三线表，没有竖线。
- 长公式和宽表格先按比例缩小（桌面最小 72%，手机 58%），再不够才在块内横向滚动，整页永远不横向滚。
- 顶栏 50px，半透明，常驻。每到原文新的一页，右侧留白标一个小小的 p.N，点它看原页。

## 颜色

暖白纸色底（`#f6f3ec`），墨色字（`#23211d`），不用纯黑纯白。只有两个强调色，各管一件事：

- 青（`#2d6173`）：AI 讨论，也用于链接。
- 赭（`#9c5f1c`）：我的笔记、我改过的地方。
- 划线是淡黄底；AI 引用的原话只画下划线，不填底色，避免和我的划线混淆。
- 深色主题是暖黑底（`#1a1917`），正文字重降到 330，避免浅字在深底上显粗；原页图反相显示。

译文、AI 讨论、我的笔记三者的区分靠字体和位置而不是颜色块：译文是正文里的宋体；讨论和笔记是边注里的黑体小字，左边一条细线，标签写明“AI · 解释”“我的笔记”。

## 保存为什么可靠

1. 文件按作者分开：agent 的只写 paper.json / discussion.json，用户的只经页面写 reader.json，谁也碰不到谁。
2. 页面先把操作放进浏览器 localStorage 队列，服务端确认落盘后才删；断线、服务没开、页面崩溃都不丢，下次自动补发。
3. 操作幂等、带时间戳，重复发送不会重复或倒退；服务端加锁、临时文件 + 原子替换写入，另记操作日志和定期快照。
4. 用户改过的段落记下改时译者稿的哈希；译者稿后来变了，页面只提示，用户选“换成译者稿”或“保留我的”。
5. 改译文时草稿每 0.4 秒存一次，误关页面再打开能恢复。
6. 写接口要页面加载时拿到的令牌，别的网页没法跨站改。
